# 线性镜头转场编辑器设计

- 状态：整体设计已获用户批准
- 日期：2026-08-21
- 产品：Storyboard Pro 短剧生产工作台
- 所属阶段：剧本
- 设计方向：横向导演台

## 1. 背景与定位

“剧本”阶段不承担小说拆解或大模型生成分镜剧本。用户在外部完成镜头拆分后，以 JSON 文件导入已经结构化的镜头剧本；本阶段负责整理镜头顺序，并明确每两个相邻镜头之间如何衔接。

该阶段的产品定位是：**导入镜头剧本、编排线性镜头顺序、设计镜头间的连续关系，并把这些关系交给后续预演和视频生成阶段执行。**

目标是减少独立生成镜头直接拼接产生的跳变感，让动作、构图、人物位置和运镜方向在镜头边界上有明确约束。

## 2. 已确认决策

用户已确认：

1. 第一版只支持线性镜头序列，不支持分支、回环或一对多连接。
2. 第一版只支持 JSON 文件导入。
3. 转场采用“预设类型 + 可展开高级参数”。
4. 没有转场数据时，为相邻镜头自动创建“连续动作”转场。
5. 镜头节点显示缩略图、编号、标题、时长和生成状态；详细信息进入检查器。
6. 镜头节点可拖拽调整顺序，系统自动处理受影响的连接。
7. 采用横向导演台：镜头是节点，转场是可选择、可编辑的节点连线，参数在右侧检查器编辑。

## 3. 核心工作流

1. 用户进入“剧本”阶段并选择“导入 JSON”。
2. 系统解析并验证文件，但不调用大模型、不改写镜头内容。
3. 系统按 `shots` 数组顺序生成横向镜头节点。
4. 存在合法 `transitions` 时加载转场；不存在时为每对相邻镜头创建默认连续动作转场。
5. 用户点击镜头查看详情，点击连线编辑转场参数。
6. 用户可拖拽镜头调整播放顺序。
7. 用户保存后，镜头顺序和转场数据写入项目状态，供预演、分镜、视频生成与合成读取。

## 4. 数据模型

### 4.1 规范 JSON

```json
{
  "project": {
    "title": "示例短片",
    "version": 1
  },
  "shots": [
    {
      "id": "shot-001",
      "title": "人物推门",
      "duration": 4,
      "thumbnail": "",
      "prompt": "",
      "videoPrompt": "",
      "dialogue": "",
      "notes": "",
      "characters": ["角色A"]
    },
    {
      "id": "shot-002",
      "title": "进入房间",
      "duration": 3.5,
      "thumbnail": "",
      "prompt": "",
      "videoPrompt": "",
      "dialogue": "",
      "notes": "",
      "characters": ["角色A"]
    }
  ],
  "transitions": [
    {
      "id": "transition-001-002",
      "from": "shot-001",
      "to": "shot-002",
      "type": "continuous",
      "duration": 0.6,
      "frameDependency": "previous_tail",
      "actionContinuity": "保持推门动作连续",
      "characterPosition": "人物从画面右侧进入",
      "cameraDirection": "继续向左跟拍",
      "notes": ""
    }
  ]
}
```

### 4.2 约束

- `shots` 数组顺序是唯一播放顺序。
- 每个镜头必须拥有非空且唯一的 `id`。
- 两个相邻镜头只能存在一条有效转场。
- 转场必须连接当前顺序中的相邻镜头。
- `from` 和 `to` 必须引用存在的镜头。
- 第一版转场类型为：`continuous`、`match_cut`、`hard_cut`、`scene_change`。
- `frameDependency` 第一版只允许 `none`、`previous_tail`、`shared_frame`：分别表示无边界帧依赖、沿用前镜头尾帧、使用独立确认的共享匹配帧。
- `duration` 统一使用秒，必须是大于或等于零的有限数值；`hard_cut` 固定为 `0`，其他类型默认 `0.6` 秒，并允许用户调整到不超过相邻两个镜头中较短镜头的时长。
- 缺失 `transitions` 或数组为空时，系统自动补齐相邻镜头转场。
- 自动生成转场默认使用 `continuous`、`previous_tail` 和 `0.6` 秒。
- 非法引用、重复镜头 ID、重复边和非相邻边必须作为可定位的导入错误显示，不得静默删除。

### 4.3 旧 JSON 兼容

导入层兼容现有镜头字段，包括 `title`、`prompt`、`negative_prompt`、`video_prompt`、`duration_sec`、`frames`、`dialogue`、`notes`、`tags`、`scene_name`、`scene_prompt` 和 `character_names`。

兼容规则集中在导入规范化层，不把旧字段分支扩散到编辑器组件。导入后在内存中统一为新版模型；再次导出时使用本规格的规范结构。源文件解析或验证失败时，当前项目保持不变。

## 5. 转场语义

### 5.1 连续动作 `continuous`

- 镜头二依赖镜头一已确认的尾帧或等价边界参考。
- `actionContinuity` 描述跨镜头延续的动作。
- `characterPosition` 约束人物在出画与入画位置上的连续性。
- `cameraDirection` 约束运镜方向，避免方向突变。
- 前置尾帧未就绪时标记为“等待边界帧”，不得显示虚假就绪状态。

### 5.2 匹配剪辑 `match_cut`

- 两个镜头围绕共同构图、动作、形状或主体特征衔接。
- 可使用单独确认的共享参考帧或匹配描述。
- 不默认等同于沿用前一镜头尾帧。

### 5.3 硬切 `hard_cut`

- 两个镜头可独立生成。
- 不要求首尾帧连续，但保留剪辑点、时长和节奏信息。

### 5.4 换场 `scene_change`

- 允许场景、地点或时间明显变化。
- 换场说明进入预演与合成数据，供后续阶段表达转场意图。

## 6. 界面设计

### 6.1 顶部工具区

- 当前项目名称。
- 镜头数量和转场数量。
- “导入 JSON”。
- 保存状态与“保存转场”。

同屏只保留一个高强调保存或推进动作，遵守导演台现有主操作层级。

### 6.2 横向镜头画布

- 镜头按播放顺序从左到右排列。
- 节点显示缩略图、编号、标题、时长和生成状态。
- 连线显示转场类型和时长，例如“连续动作 · 0.6s”。
- 画布支持横向平移；长项目不压缩节点到不可读尺寸。
- 单击节点选择镜头，单击连线选择转场，两者使用明确且不同的选择状态。
- 拖拽节点重新排序时显示插入位置，落下后再更新数据。

### 6.3 右侧检查器

选择镜头时显示镜头详情，包括提示词、人物、对白、场景与备注。第一版以查看为主，是否允许直接编辑镜头内容由实现计划按现有能力决定，不阻塞转场编辑。

选择连线时显示转场编辑器：

- 基础参数：转场类型、转场时长。
- 高级参数：首尾帧依赖、动作延续、人物位置、运镜方向、备注。

参数保存成功后立即更新连线标签和项目脏状态；关闭检查器不会丢失已经明确保存的修改。

### 6.4 响应式

- 桌面：横向画布与右侧检查器并列。
- 紧凑窗口：检查器改为可开合抽屉。
- 手机：镜头链可横向滑动，转场参数使用底部抽屉。
- 触控目标至少 44×44 CSS px，不依赖悬停发现关键操作。

## 7. 重排与删除规则

### 7.1 重排

镜头顺序改变后：

1. 原来相邻且重排后仍相邻、方向未变的镜头保留原转场。
2. 新形成的相邻关系创建默认连续动作转场。
3. 不再相邻的转场从活动序列移除。
4. 重排作为单次可撤销操作记录，避免连续边更新形成多步撤销噪声。

### 7.2 删除

- 删除镜头前显示将受影响的前后转场。
- 删除后，原前驱与后继变为新相邻关系时创建默认连续动作转场。
- 只有一个镜头时不创建转场；没有镜头时展示导入引导空状态。

## 8. 状态与数据流

```text
JSON 文件
   │
   ▼
解析与兼容规范化 ──失败──→ 可定位错误列表，项目不变
   │成功
   ▼
Storyboard 项目状态：shots 顺序 + transitions
   │
   ├─→ 横向镜头画布
   ├─→ 镜头 / 转场检查器
   ├─→ 空间预演与分镜阶段
   └─→ 连续性规划、视频生成与最终合成
```

转场数据必须成为共享领域数据，而不是只存在于界面组件的临时状态。后续阶段读取同一份 `transitions`，避免出现“剧本阶段设置成功，但生成阶段未消费”的断链。

现有 `VideoBoundaryKind` 和连续性规划逻辑可作为实现基础；设计不要求重写已有视频生产控制器。

## 9. 错误与恢复

- 文件不是合法 JSON：显示解析位置或可理解的格式错误。
- 缺失 `shots`：说明所需顶层结构。
- 重复或缺失镜头 ID：列出对应镜头索引。
- 非法转场类型：显示支持的类型。
- 转场引用缺失镜头或非相邻镜头：显示转场 ID、`from` 和 `to`。
- 导入失败不覆盖当前项目，也不留下半导入状态。
- 保存失败保留用户当前编辑，并提供重试。
- 存在未保存修改时，离开阶段或重新导入前给出明确提示。

## 10. 可访问性与键盘操作

- 镜头和转场都可通过键盘选择，并有可见焦点。
- 画布提供线性语义顺序，使屏幕阅读器能按“镜头、转场、镜头”理解内容。
- 拖拽排序提供键盘替代操作，例如“向前移动 / 向后移动”。
- 转场类型不只依赖颜色表达，连线必须显示文字。
- 错误摘要获得焦点，并可跳转到具体问题。
- 抽屉打开后管理焦点，关闭后返回原触发元素。

## 11. 测试与验收

### 11.1 数据合同

- 新版 JSON 完整导入。
- 旧字段规范化。
- 缺少 `transitions` 时自动补边。
- 重复 ID、非法类型、缺失引用、非相邻边被拒绝并准确报告。
- 导入失败不改变原项目。

### 11.2 编辑行为

- 节点与连线选择切换正确的检查器内容。
- 修改基础和高级参数后保存并重新加载仍一致。
- 拖拽重排只保留仍有效的旧转场，并为新邻接补默认转场。
- 删除镜头正确处理相邻转场。
- 只有零个或一个镜头时边界行为正确。
- 键盘可以完成选择、重排和参数编辑。

### 11.3 下游集成

- 四种转场被连续性规划器正确区分。
- 连续动作的尾帧依赖会形成真实的待满足状态。
- 转场时长和高级参数进入预演、视频生成或合成输入。
- 保存、关闭项目、重新打开后镜头顺序与转场保持一致。

### 11.4 视觉验收

- 1440×900：画布与检查器并列，三至四个节点可读。
- 1024×768：检查器抽屉不遮断关键画布操作。
- 390×844：镜头链可滑动，底部参数抽屉与导演台导航不重叠。
- 各视口检查横向溢出范围、选择状态、连线标签、44px 触控目标和未保存提示。

## 12. 非目标

- 不把小说自动拆成镜头剧本。
- 不在第一版接入大模型。
- 不支持 Word、Excel、PDF 或纯文本导入。
- 不支持自由节点图、分支剧情、回环或并行镜头。
- 不重写现有分镜生成、视频生成或 ComfyUI 工作流。
- 不在本阶段直接生成最终视频；本阶段定义并保存边界意图。
- 不以单纯视觉连线代替下游真实消费转场数据。

## 13. 实施边界

实施应优先复用现有 storyboard 类型、项目状态、`VideoBoundaryKind`、连续性规划器和 Director Desk 外壳。新增职责应分为导入规范化、线性序列与转场领域操作、画布/检查器界面、持久化与下游适配，不把所有逻辑堆入“剧本”页面组件。

当前工作区存在大量其他未提交修改。后续实施必须严格限定文件范围，禁止重置、清理或覆盖与本功能无关的用户改动。
