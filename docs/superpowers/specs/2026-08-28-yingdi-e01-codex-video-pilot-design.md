# 《影帝他总想对我图谋不轨》第1集 Codex 分镜与视频样片设计

日期：2026-08-28

## 1. 目标与边界

以现有改编剧本第1集为唯一剧情依据，制作一支约2分钟的完整效果样片。现有剧本包含36个剧情节拍、预估106.9秒，本次采用约23镜头的平衡方案：保留完整剧情、关键动作和结尾悬念，同时控制资产、生图和视频任务数量。

本次范围包括：资产盘点、Codex 补生人物/场景/道具、资产审核、23镜头分镜生成、分镜审核、逐镜视频生成、视频审核、对白/心声/音效与约2分钟预览合成。

所有 Codex 资产和分镜候选都必须进入 `needs_review`。未经用户接受的候选不得成为正式资产、正式分镜或视频输入。视频阶段仅在全部正式分镜通过用户审核后开始。

## 3. 内容结构与镜头预算

### 3.1 棺中惊醒：5镜

睁眼、呼救、拍击棺盖、辨认环境、发现锦缎与铜钉。重点建立狭窄空间、呼吸压力和人物受困事实。

### 3.2 含元殿闪回：4镜

宫宴、晚翠劝酒、酒杯坠地、蒙面人拖行。现实与记忆通过声桥、白闪或动作匹配衔接。

### 3.3 绝境自救：6镜

肩顶棺盖、拔簪划缝、发簪折断、指尖受伤、以公主身份呼救、意识衰弱。重点表现动作受力和恐惧转为求生意志。

### 3.4 墓外回应与开棺：4镜

外部重击、棺缝透光、韦训回应、匕首撬开棺盖。光线和声音逐步扩大，形成第二次情绪抬升。

### 3.5 凤凰胎悬念：4镜

韦训逆光出现、盗墓短铲特写、凤凰纹暗板、凤凰玉佩与暗板呼应。最后停在李宝珠伸手又停住的戒备动作上。

实施时允许在22–24镜内微调，但不得删去五段中的关键剧情节点，也不得改变106.9秒对白与动作的基本顺序。

## 4. 资产系统

### 4.1 资产盘点

正式生成前建立资产清单，记录资产 ID、类型、状态、参考图、用途、出现镜头和审核结果。已存在且质量合格的资产直接复用，不重复生成。

### 4.2 人物资产

- 复用：李宝珠、韦训身份定妆图。
- 补生：晚翠、蒙面拖行者。
- 变体：李宝珠棺中破损礼服版本，必要时补充脸部、身体服装和受伤手指局部参考。
- 人物参考用途：`face_identity`、`body_costume`、`pose_reference`。

### 4.3 场景资产

- 密闭棺内：无人物空间图、棺盖内面、锦缎、棺缝与铜钉位置。
- 墓室外部：棺木落位、韦训站位、主要光源和开棺方向。
- 含元殿宫宴：灯火、席位、酒案和人物动线。
- 冰冷石阶：蒙面人拖行的空间、材质和光线。
- 场景优先生成无人物空间权威图，主要用途为 `spatial_authority`、`lighting_only` 和 `style_only`。

### 4.4 道具资产

梓木棺、粗大铜钉、完整发簪、折断发簪、桂花酒杯、匕首、盗墓短铲、凤凰纹暗板、凤凰玉佩。关键状态必须分别记录，避免模型在镜头间自行改变道具结构。

### 4.5 资产审核

每项资产先生成一张主候选；人物按需要补充正面、侧面或局部图。审核检查身份、比例、材质、时代感、状态和是否适合后续多镜复用。候选只有在用户接受后才能写入正式资产绑定。

## 5. Codex 分镜任务包

每个镜头建立独立 Codex 任务包，参考图按以下优先级排列：

1. `spatial_authority`：机位、空间几何、人物位置、遮挡和构图。
2. `pose_reference`：动作、受力方向和接触关系。
3. `face_identity`：脸型、五官、发型和身份。
4. `body_costume`：成年体型、服装结构、破损状态和配饰。
5. `prop_detail`：本镜头关键道具及其状态。
6. `style_only`：国风半写实3D材质、色盘和电影灯光，不得控制构图。

任务包同时冻结剧情、对白语境、镜头动机、景别、机位、人物数量、可见肢体、动作接触、输出比例和禁止项。生成前验证所有参考路径、摘要和用途说明；生成后保持不可覆盖的候选与结果清单。

分镜质量门包括：人物身份与服装连续、人数正确、双手和肢体完整、空间关系正确、动作受力可信、道具状态一致、相邻镜头视线/光线/位置连续、无文字水印、画面为16:9。失败镜头只重做自身。

## 6. 双阶段审核门

### 阶段A：资产与分镜

先完成全部缺失资产和约23张分镜候选。用户可以逐项或按批次接受/拒绝；只有全部必要资产和分镜成为正式版本后，阶段A才完成。

### 阶段B：视频

阶段A完成并获得用户明确确认后，才允许生成视频。视频任务只能读取正式分镜路径，不得读取 `needs_review` 候选路径。

## 7. 视频生成与成片

### 7.1 生成模式

- 情绪、呼吸和轻微视线变化：单帧图生视频。
- 拍棺、划缝、发簪折断、重击、撬棺等有明确落点的动作：首尾帧视频。
- 闪回、棺盖开启和凤凰胎揭示：单独设计尾帧及转场。

每段约3–6秒，23段合计约107秒；用片头建立、段落停顿和结尾悬念将成片控制在约120秒。

### 7.2 视频提示词

每镜提示词必须包含身份与服装锚点、场景锚点、动作起止、表情弧线、摄像机运动、环境动态、对白或心声规则、禁止形变和禁止换景。心声镜头保持闭口；对白镜头才允许口型。

### 7.3 视频审核

逐镜检查人脸、服装、棺木、场景和道具漂移，肢体完整性，动作落点，镜头运动，首尾边界和相邻连续性。单镜失败独立重试，不触发整集重跑。只有审核通过的视频才能加入时间线。

### 7.4 音频与合成

加入李宝珠、韦训、晚翠对白，李宝珠心声，棺内呼吸与拍击回声，墓室重击、铜钉松动、木屑、匕首撬动等音效。使用闪回声桥、白闪或动作匹配连接现实与记忆。最终输出约2分钟预览版，并保留逐镜视频和独立音轨。

## 8. 组件与数据流

流程组件保持单一职责：

- 文本/节拍解析器：读取第1集36个节拍并映射到约23镜。
- 资产盘点器：判断复用、缺失和变体需求。
- Codex 资产任务：生成缺失人物、场景和道具候选。
- 资产审核门：只发布用户接受的资产。
- 分镜编译器：组装有序多参考图和镜头约束。
- Codex 分镜任务：生成不可覆盖的候选与 lineage 结果。
- 分镜审核门：只发布用户接受的正式分镜。
- 视频任务编译器：从正式分镜产生单帧或首尾帧任务。
- 现有视频引擎：逐镜生成视频。
- 视频审核与时间线：管理重试、连续性、音频和预览导出。

数据流：剧本节拍 → 镜头计划 → 资产清单 → Codex 资产候选 → 资产审核 → 正式资产绑定 → Codex 分镜候选 → 分镜审核 → 正式分镜 → 视频任务 → 视频审核 → 音频与合成。

## 9. 错误处理与恢复

- 缺少参考路径或摘要不一致：生成前失败，不创建可发布结果。
- Codex 生成失败：保留任务记录，允许同镜重试，不影响其他任务。
- 空间/身份/道具漂移：拒绝候选，调整对应参考或用途说明后重做。
- 视频引擎不可用：停止在已审核分镜阶段，不降级使用未授权网络服务。
- 单镜视频失败：保留已通过视频，只重试该镜。
- 应用崩溃或重复导入：依赖既有 lifecycle、摘要和幂等机制恢复，不自动接受候选。
- 拼接前校验：任何镜头缺失、状态非 accepted、时长异常或文件摘要变化均阻止整片导出。

## 10. 验证与成功标准

### 自动验证

- 镜头总数在22–24之间，剧情节拍全部被覆盖且顺序不变。
- 资产和分镜候选都具有用途、摘要、状态和审核记录。
- 视频任务只引用正式分镜。
- 所有输出文件存在、可解码、时长和分辨率符合任务记录。
- 聚合时长约120秒，24fps，16:9。
- 失败任务可以独立重试，已接受结果不被覆盖。

### 人工成功标准

- 五段剧情清晰，开场受困事实、绝境求生和凤凰胎悬念成立。
- 李宝珠、韦训和晚翠身份稳定，服装与道具状态连续。
- 棺内空间可信，拍击、划动、受伤和开棺动作有明确受力。
- 闪回与现实可辨且衔接自然。
- 对白、心声、动作和音效节奏匹配。
- 用户可以在阶段A审核完整资产与分镜，并在确认后独立启动阶段B视频生成。
