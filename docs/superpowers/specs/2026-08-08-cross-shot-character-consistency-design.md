# 跨镜头人物脸部与发型一致性设计

日期：2026-08-08

## 1. 目标

为 AI 漫剧分镜建立可商业使用、适配 RTX 5070 Ti 16GB 显存的角色一致性生产链。首要目标是在跨镜头、不同视角、不同景别和不同光照下保持同一角色的脸型、五官比例与发型结构稳定。

本次同时解决当前流水线中以下问题：

- 双人 Stage B 同时接收场景、姿态和多张人物参考，条件之间互相争夺注意力。
- 人物在部分远景中只占画面约 2%–6%，模型没有足够像素稳定表现五官。
- 失败结果会被参考图抠图补救并继续报告为成功，掩盖真实质量问题。
- 多套 ComfyUI 路径、旧定制节点和缺失依赖增加维护成本。

## 2. 硬件与授权边界

目标机器为 NVIDIA GeForce RTX 5070 Ti 16GB，系统内存约 48GB，使用 ComfyUI Desktop。生产模型和工作流必须允许商业发布或商业变现。

候选模型：

- `Qwen-Image-Edit-2511`：Apache 2.0，作为首选生产基线。官方版本增强了人物、多人物一致性和编辑漂移控制，且与现有 Qwen 流程迁移成本最低。
- `FLUX.2 Klein 4B`：Apache 2.0，作为快速候选和回退模型。官方 ComfyUI 数据显示四步蒸馏版约需 8.4GB 显存，适合本机推理。
- `FLUX.2 Klein 9B` 和 `FLUX.2 Dev`：开放权重版本具有非商业许可限制，不进入本项目生产候选。

角色 LoRA 训练与日常推理解耦。Qwen 训练可通过逐层 CPU/GPU 卸载尝试在本机执行，但以稳定性和耗时为准；Klein 4B 官方训练参考以 24GB 显存为宜，必要时使用短时云 GPU，训练产物回到本机推理。

## 3. 总体架构

流水线采用“角色身份包 + 专属 LoRA + 场景先行 + 人物分层 + 局部精修 + 自动验收”。

```text
角色身份包
  -> Qwen 2511 / Klein 4B 八镜头基准测试
  -> 选定主模型并训练角色 LoRA
  -> 生成干净场景与姿态布局
  -> 逐角色生成透明人物层
  -> 分层合成
  -> 脸与发型局部高分辨率精修
  -> 自动一致性评分
  -> 仅重做不合格角色区域
```

Qwen 2511 与 Klein 4B 通过同一个人物生成接口接入。两者使用相同输入契约和八镜头测试集，但同一镜头不得混用两个基础模型，避免画风和材质漂移。测试胜者成为默认生产模型，另一模型只作为整个人物层的回退。

## 4. 角色身份包

每个主要角色具有独立、版本化的身份包：

- `face_master`：无遮挡、中性表情的正脸近景。
- `face_left`、`face_right`：左右 45° 脸部参考。
- `hair_back`：后脑、发尾和发饰结构参考。
- `body_front`、`body_side`、`body_back`：全身比例、服装结构和配色参考。
- `expression_neutral`：防止训练把强表情误学为身份。
- `identity.json`：角色触发词、脸型、眉眼、瞳色、刘海分区、发色、发饰、体型、服装版本和禁改项。

换装创建新的服装版本，不覆盖角色本体身份。普通生成结果不得自动加入身份包或训练集；只有人工或规则审核通过的英雄帧可以成为补充参考，并产生新的身份包版本。

## 5. LoRA 数据集

每名主要角色使用 15–30 张审核图，至少覆盖：

- 正脸、左右 45°、左右侧面和背面。
- 近景、半身和全身。
- 中性表情及少量自然表情。
- 不同背景、镜头、动作和光照。

所有训练图必须保持同一脸型、发型结构、发色和服装版本。背景与动作必须多样，避免 LoRA 记住固定场景或固定姿态。每个角色使用唯一触发词；双人镜头必须显式绑定角色 ID，不使用“男人”“女人”等模糊标签代替身份。

数据构建顺序：当前三视图生成候选角度和表情，筛除身份漂移图，发布身份包 v1，训练 LoRA，运行八镜头回归，合格后发布角色模型版本。

## 6. 逐镜头生成流程

### 6.1 场景与布局

先生成不含可见人物的干净场景，只确定镜头、透视、光线、地面接触和人物落点。姿态图负责动作和朝向，不负责人物身份。

### 6.2 参考图路由

系统根据人物朝向和景别自动选取参考：

- 正面或小角度：`face_master + body_front`。
- 左右侧面：对应侧脸 + `body_side`。
- 背面：`hair_back + body_back`。
- 近景：脸部身份优先。
- 全身和远景：发型轮廓、服装色块与身材比例优先。

单次人物生成输入限制为三类：当前场景裁切、当前角度身份参考、当前镜头姿态图。LoRA 作为常驻模型条件，不再同时向编辑模型注入全部三视图和无关场景参考。

### 6.3 分角色生成

每个角色单独生成透明人物层。双人或多人镜头逐角色生成和合成；后生成的角色不得重新编码或重绘已通过验收的角色。人物层需要保留遮罩、落点、缩放、角色 ID、身份包版本、LoRA 版本和生成参数，便于局部重试。

### 6.4 脸与发型精修

中景和近景将头肩区域提升到约 512–768 像素进行局部重绘，使用同一角色 LoRA 和 `face_master`。局部精修只允许修改脸、发际线、刘海、发尾和发饰，随后缩回镜头并进行边缘、色温、颗粒和光照融合。

远景不强行生成或验收精细五官，只检查发型轮廓、服装色块、体型和角色可辨识度。

## 7. 一致性评分

评分按镜头类型动态加权，不使用单一真人 FaceID 阈值判断现代国漫角色：

- 脸部身份：脸型、眉眼位置、鼻口比例、年龄感。
- 发型身份：刘海分区、侧面轮廓、后脑形状、发色和发饰。
- 服装身份：主色、领口、袖型、饰品和轮廓。
- 身材比例：头身比、肩宽、腿长和体型。
- 画面质量：多脸、五官破损、发丝粘连、重复肢体和人物缺失。

每个角色通过身份包建立自己的评分基线。近景提高脸部分权重，背面提高发型权重，远景降低脸部分并提高轮廓与服装权重。

## 8. 失败处理

失败采用有界重试，不把低质量补救结果标记为成功：

1. 保持构图和参考不变，只调整随机种子。
2. 扩大头肩或人物遮罩，提高局部生成分辨率。
3. 加入同角度的已审核英雄帧；`face_master` 始终保持最高身份优先级。
4. 使用备用模型重新生成完整人物层。
5. 仍不合格则标记为“需要人工审核”。

上一镜头只能作为低权重连续性参考，不能取代角色身份包，避免错误逐镜头累积。重试只影响失败角色层，不得重绘场景或已通过的其他人物。

## 9. 界面设计

### 9.1 角色资产面板

显示身份包版本、LoRA 版本、训练状态、缺失角度、服装版本和最近一次八镜头回归结果。

### 9.2 镜头检查卡

显示脸部、发型、服装、身体和总体一致性分数，提供身份参考与生成结果对照，并标明实际使用的模型、LoRA、参考图和失败原因。

### 9.3 单角色重绘

用户可以只重绘某个镜头中的某个角色，并选择重绘范围为脸发、上半身或完整人物层。场景和其他人物保持不变。

## 10. 测试与验收

固定回归集包括：

1. 正脸近景。
2. 45° 半身。
3. 左右侧脸。
4. 背面。
5. 全身动作。
6. 强表情。
7. 双人同框。
8. 不同光线下的同一人物。

每次更换基础模型、LoRA、身份包或提示词模板都必须重跑。发布门槛：

- 不得出现人物丢失、串脸、额外人物或身份互换。
- 发型结构在所有可见头部镜头中保持可辨识。
- 中近景脸部必须通过角色专属阈值。
- 服装版本和主色不得无指令变化。
- 回归报告包含每镜头分项分数、耗时、显存峰值、重试次数和最终状态。

## 11. 迁移范围

实施阶段包含：

- 新增角色身份包和 LoRA 版本数据结构。
- 抽象 Qwen 2511 与 Klein 4B 人物生成提供器。
- 将现有双人 Stage B 改为逐角色人物层生成。
- 新增参考路由、局部脸发精修、动态评分和有界重试。
- 在资产面板和镜头面板加入身份与质量控制 UI。
- 建立八镜头回归脚本和模型对比报告。

本次不包含视频逐帧一致性、口型同步、声音身份或三维角色资产生成。
