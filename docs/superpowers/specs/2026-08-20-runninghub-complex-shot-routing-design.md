# RunningHub 复杂镜头审批路由与水印修复设计

## 目标

在保留本地 MiniMax H3 双人物参考工作流作为默认生产路径的前提下，为多角色接触、连续快速动作、复杂运镜以及本地多次生成仍不达标的镜头增加 RunningHub 云端候选路径。系统只提出建议并准备任务；任何会产生云端费用的提交都必须由用户明确确认。

云端结果进入现有视频质量门之前，必须先取得可验证的 MP4，并处理 RunningHub 烧录水印。处理失败或质量不足的素材只能进入人工复核，不能自动成为交付素材。

## 已验证事实

- 当前 RunningHub “MiniMaxH3 参考加速版”使用两张启用的人物设定图，其他参考输入关闭。
- 当前目标参数为 16:9、约 0.9MP、8 秒，生成主路径为 H3 R2V、Turbo LoRA、SageAttention 和 `VHS_VideoCombine`。
- 后置 `RIFE VFI` 可能因 `Tensor type unknown to einops <class 'tuple'>` 报错，但报错前的 `VHS_VideoCombine` 可能已经输出有效 MP4。
- 已下载样片的左上角“RunningHub AI生成”水印烧录在视频帧中，并非网页预览叠层。
- 本机已安装 RH OpenAPI ComfyUI 插件；API 密钥属于本地运行配置，不能写入项目文件、日志或生成凭证。

## 范围

本阶段包括：

- 镜头复杂度评估与云端建议；
- 提交前审批；
- RunningHub 任务准备、提交、轮询、结果回收与凭证；
- `VHS_VideoCombine` 主输出识别；
- 无水印源文件优先获取；
- 烧录水印检测、时序修复和质量复核；
- 云端结果接回现有视频质量门。

本阶段不包括：

- 未经用户确认自动扣费；
- 把 RunningHub 作为所有镜头的默认提供方；
- 修改或删除用户现有云端工作流；
- 将 RIFE 插帧作为生成成功的必要条件；
- 用固定裁切无条件损失镜头构图；
- 自动发布或导出未通过质量门的视频。

## 路由模型

每个镜头先进入本地路由。以下任一条件可将其标记为 `cloud_recommended`：

1. 两名及以上角色发生身体接触、遮挡交换或道具交接；
2. 同一镜头包含两个及以上需要严格排序的快速动作节拍；
3. 镜头同时要求明显角色运动和明显相机运动；
4. 存在追逐、搏斗、群体包围等高动态空间关系；
5. 本地生成连续达到配置的重试上限，仍未通过人物、姿态、视线、动作或空间连续性质量门。

`cloud_recommended` 只是建议状态。系统不得在生成建议时调用 RunningHub。用户仍可选择继续本地生成或跳过镜头。

## 审批流程

审批面板展示以下不可隐藏的信息：

- 镜头编号、时长、分辨率和复杂度原因；
- 两张实际提交的人物设定图预览及顺序；
- 完整视频提示词和关键动作节拍；
- RunningHub 工作流名称、固定版本标识和目标参数；
- 云端可能计费、水印可能需要修复的提示；
- `确认提交`、`继续本地`、`取消` 三个明确操作。

只有 `确认提交` 才创建不可复用的一次性审批令牌并提交任务。审批令牌绑定镜头输入摘要、工作流版本、参考图摘要、提示词摘要和参数摘要；任一输入发生变化，旧令牌立即失效并要求重新确认。

## RunningHub 适配器

已安装 RH OpenAPI 插件的官方 README 明确将其定义为 RunningHub “标准模型 API”的 ComfyUI 实现；这不能证明它可以调用用户保存的整张自定义工作流。第一版因此采用下述人工页面回退作为生产传输：系统在审批后生成素材包并打开固定工作流页面，最终 `运行` 操作仍由用户在 RunningHub 内完成。只有取得公开、可验证的自定义工作流 API 契约并再次批准后，才启用自动提交。适配器边界保持为：

- `prepare`：验证工作流版本、两张参考图、参数和审批令牌，不访问计费接口；
- `submit`：第一版记录用户从 RunningHub 页面取得的真实 `taskId`；未来自动传输必须使用本地安全配置读取 API 密钥；
- `poll`：第一版由用户刷新页面状态并导入结果；未来自动传输必须使用有界轮询并支持取消和超时；
- `collect`：枚举所有输出，优先选择 `VHS_VideoCombine` 生成的有效 MP4；
- `attest`：记录提供方、任务 ID、工作流版本、输入摘要、输出摘要、时间和终态。

若 RunningHub 报告整个任务失败，但已经存在可下载且可解码的 `VHS_VideoCombine` MP4，适配器将其标记为 `recovered_primary_output`，保留下游 RIFE 错误作为警告。不能将不存在、不可下载、无法解码或时长异常的预览伪装成成功输出。

人工 RunningHub 页面操作回收时必须录入任务 ID 并验证视频。该回退不允许绕过审批和质量门，也不得读取浏览器 Cookie、请求头、令牌或其他登录凭据。

## 水印处理

水印处理使用分层策略，不假设水印背景一定是天空或纯色：

1. **原始素材优先**：检查任务产物和下载接口，优先获取没有烧录水印的原始 MP4。
2. **水印检测**：在左上角归一化候选区域内跨多帧检测固定文字结构；同时抽查其他区域，防止位置或尺寸变化。没有可靠检测结果时不自动修复。
3. **时序修复**：根据跨帧稳定水印蒙版进行视频级内容修复，利用前后帧和运动信息补全背景。处理按镜头分块运行，以适配本机 16GB 显存，并保持原分辨率、帧率、时长和音轨。
4. **保守回退**：仅当构图安全区明确允许时，才可在用户复核后使用裁切加等比缩放；固定模糊块、贴片遮盖和无条件裁切不作为自动生产方案。

修复结果必须通过水印残留、局部闪烁、纹理拉扯、边缘重影、分辨率、帧率、时长和音轨完整性检查。未通过时保留原片和修复片，状态设为 `watermark_review_required`。

## 状态与数据流

镜头云端状态使用以下单向流转：

`local_default -> cloud_recommended -> awaiting_approval -> approved -> submitted -> running -> output_collected -> watermark_checked -> quality_review -> accepted`

`recovered_primary_output` 是主视频已从下游失败任务中恢复的非终态，下一步必须进入 `watermark_checked`。错误或用户动作可进入 `declined`、`cancelled`、`timed_out`、`failed` 或 `watermark_review_required`；这些终态不能被后台轮询静默改回运行态。

数据流为：

`镜头合同 -> 复杂度评估 -> 审批快照 -> RunningHub -> 主 MP4 回收 -> 水印检查/修复 -> 标准化 -> 现有视频质量门 -> 时间线`

## 质量门

云端并不降低现有验收要求。进入成片前至少检查：

- 人物脸部、发型、服装和体型与两张设定图一致；
- 3D 国漫画风稳定，不退化为真人写实；
- 角色视线指向叙事目标；
- 动作节拍顺序正确，角色和道具没有瞬移；
- 相邻镜头的站位、朝向、姿态和场景空间连续；
- 水印不可见，修复区域无明显闪烁或破损；
- 视频可解码，时长、分辨率、帧率和音轨符合镜头合同。

任何单项失败都不得自动覆盖已批准的本地版本。

## 安全与费用约束

- API 密钥只从 RH OpenAPI 本地设置、环境变量或本机私有配置读取，日志只记录配置来源，不记录密钥值。
- `submit` 必须同时验证有效审批令牌与当前输入摘要，禁止刷新页面、恢复会话或后台重试触发重复扣费。
- 网络失败后默认进入待处理状态，不自动创建第二个任务；必须先按输入摘要和任务 ID 查询是否已经提交。
- 取消只取消当前任务，不删除本地原片、云端结果或其他工作区文件。
- 所有下载写入按任务 ID 隔离的新目录，禁止清理用户指定的现有目录。

## 测试与验收

自动测试覆盖：

- 简单镜头保持本地默认，复杂镜头仅产生建议；
- 未审批、审批过期和输入变更后均不能提交；
- 同一审批令牌不能重复扣费；
- 两张参考图顺序、提示词和工作流版本进入输入摘要；
- RIFE 失败但主 MP4 有效时可恢复，主 MP4 无效时必须失败；
- 任务超时、取消、网络中断和恢复轮询的状态一致性；
- API 密钥不出现在日志、凭证和项目持久化数据中；
- 水印检测阴性不误修复，阳性进入修复，修复失败阻止交付；
- 标准化后的视频元数据和音轨保持不变；
- 云端视频必须继续通过人物、动作、空间连续性和视频质量门。

人工验收至少包含：

1. 简单单人镜头，确认不会建议云端；
2. 林越与岚的双人并行动作镜头，确认提交前展示两张正确设定图；
3. 林越、岚与狼群的复杂交互镜头，确认动作、视线和空间关系；
4. 一条 RIFE 后置失败但主 MP4 已生成的任务，确认可回收且保留警告；
5. 天空、树林、人物遮挡三类水印背景，确认修复不闪烁、不破坏主体；
6. 修复不合格样片，确认只能进入人工复核而不能进入成片。

## 完成标准

- 用户可以看见系统为何建议云端，并可在不产生费用的情况下拒绝；
- 每次云端提交都有与当前输入严格绑定的人工确认；
- RunningHub 主视频能被可靠回收，后置 RIFE 错误不会造成误判；
- 水印处理适用于不同背景和镜头运动，不依赖固定裁切；
- 未通过水印和内容质量门的素材不会进入时间线交付；
- 本地 H3 路径、现有项目数据和其他 dirty/untracked 文件不受影响。
