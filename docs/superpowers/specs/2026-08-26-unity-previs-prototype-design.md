## 5. 场景和交换协议

- 交换包使用独立 `schemaVersion`，携带源场景、镜头、相机、快照 ID 和输入摘要。
- 保留来源 JSON 副本；Unity 修改后保存新版本，不直接改写正式项目。
- 对只读未知字段保留来源信息；对不支持的几何、姿态或约束明确报错，不丢弃后继续宣称成功。
- 现有 SceneStage 的右手、Y 向上、米制作为外部标准；Unity 内部坐标转换只在适配边界进行。
- 位置、四元数、相机朝向、法线及骨骼空间均须验证往返。禁止仅翻转位置而不转换姿态。
- 交换格式明确区分根变换、父关节局部旋转及世界关节坐标，避免重复应用根变换。
- 相机统一垂直 FOV、宽高比、near/far 和输出尺寸；不能用编辑视角代替镜头相机导出。
- 选择的源快照或相机缺失时停止，不自动使用第一个镜头。

## 6. 最小可交互预演

人物采用可见的分节灰模：头、躯干、骨盆、上下臂、掌部、指链、大小腿和脚。关节层级提供可保存的局部旋转；不要把单个胶囊当作完整人体姿态。

提供场景选择、实体选择、根变换编辑、关节旋转编辑、相机编辑、保存和导出。无需重做完整 DCC 界面。

容器由独立底板、侧壁和顶盖组成，杯子、桌面为独立实体。相机可位于封闭容器内部，不能为了看见人物而偷偷移除应参与遮挡的顶盖。

接触目标来自通用数据：主体挂点、目标实体、局部接触点和容差。首版提供编辑及预检；不能靠接触误差检查冒充自动 IK 求解。

## 7. 输出契约

每次导出使用独立运行目录，输出清单包含相机参数、输入摘要、尺寸、编码、SHA-256 和预检结果。

控制图包括完整灰模颜色图、深度图、法线图、逐实体可见遮罩、独立主体遮罩、身体骨架图、手部骨架图和接触诊断图。

- 可见遮罩必须保留其他几何的深度遮挡；独立主体遮罩必须另行标识，不得当作可见区域。
- 深度明确使用线性相机空间距离，记录 near/far 及映射方式；导入器按下游模型编码要求转换，不能将原始 GPU depth 或 Three.js RGBA packing 当作通用灰度图。
- 法线声明所在空间与 RGB 映射；控制数据不应用美术后处理、色调映射或不明确的 gamma 转换。
- 实体 ID 与二值遮罩不允许抗锯齿产生未声明类别值。
- OpenPose 图按明确关节编号和连线输出，不用人物轮廓替代；手指链与身体骨架分别核对。
- Unity 图像必须来自同一实际场景与镜头相机；禁止用手绘示意图替代渲染证据。
- 导入既有分层控制包前校验文件真实存在、PNG 可解码、尺寸、摘要及输入版本；旧输入的控制包必须失效。

## 8. 预检和错误处理

导出前校验实体引用、非有限数值、相机裁剪参数、骨架缺失、容器内部关系和接触距离。通用预检输出具体实体、挂点、测量值和容差。

几何复杂度超出首版验证能力时明确报告“不支持精确碰撞验证”，不能以包围盒检查声称任意网格无穿模。

输入错误、Unity 编译失败、许可失败、控制图缺失或哈希不符均停止当前步骤并保留日志。取消导出不会覆盖上一组有效结果。

## 9. 分阶段验收

### A. 环境与协议

Unity 实际启动和编译成功；可加载两个场景数据；坐标、关节与相机往返测试通过。保存后重新打开得到相同姿态和构图。

### B. 真实空间画面

容器场景：人物横躺在内部，顶盖存在，双掌接触顶部，前景几何按深度正确遮挡。桌后场景：身体被桌面或桌沿合理遮挡，杯子与指定手部接触。人工检查可见手指数量和关节连接。

使用同一代码加载两个数据集；对调实体 ID 后行为不变。故意移动人物到容器外、移动手离开目标后，预检必须失败。

### C. 控制图与回读

使用实际 Unity 渲染图检查骨架与人体、深度与遮罩对齐。控制包可被适配器验证并关联回准确的镜头与快照。改变相机或姿态后旧包失效。

### D. AI 链路试验

仅在 A–C 通过且输入预览确认后，使用现有本地流程生成候选，保留原图。单独审核空间、身份、手部及遮挡；通过自动检查不能替代人工成图验收。

若 Unity 灰模正确而 AI 成图仍错误，返回下游控制编码、控制强度或分层合成排查，不据此继续扩大引擎迁移。
