# Novel Action Director 设计说明

日期：2026-08-22

## 目标

新建 `novel-action-director` skill，在剧本与分镜之间增加独立的人物动作与表演导演层：

```text
novel-script → script.json
                    ↓
        novel-action-director → action.json
                    ↓
          novel-storyboard → storyboard.json / H3 提示词
```

它将剧本中的动作/表演关键节拍深化为可对账、可校验、可供 AI 视频生成消费的动作计划，解决静态摆拍、动作缺乏惯性与受力、双人互动不完整、微表情只有标签、复杂道具和战斗动作连续性差等问题。

## 职责边界

### 输入

- 必需 `script.json`：场次、节拍、动作、台词与时长事实。
- 可选 `cast.json`：角色身体条件、性格、动作习惯及稳定形象事实。
- 可选 `art.json`：表演区域、出入口、障碍物、叙事道具与空间锚点。
- 题材物理档位：`realistic / wuxia / xianxia / stylized`。

### 输出

- `action.json`：结构化动作与表演计划。
- Markdown 动作导演稿。
- 单页 HTML 评审报告。
- 面向 `novel-storyboard` 的精简动作摘要。

### 做什么

- 识别并深化情绪转折、微表情、双人接触、复杂道具、追逐、跌倒、救援、战斗、受击及需要镜头强调的动作爆点。
- 描述动作的起点、阶段、接触/受力、反应、恢复及终点。
- 记录身体重心、支撑、轨迹、左右手、道具、视线、关系距离、次级运动和生成风险。
- 将动作结果和首尾状态交给分镜层消费。

### 不做什么

- 不改台词，不新增角色、剧情事实或结果。
- 不决定切几镜、景别和具体运镜。
- 不替代 `novel-characters` 的长期角色设定。
- 不替代 `novel-art` 的场景资产和空间覆盖设计。
- 不执行视频生成、剪辑或动作捕捉。

`cameraIntent` 只声明观众必须看清的信息与动作瞬间，最终镜头方案仍由 `novel-storyboard` 决定。

## 按需深化策略

不是所有节拍都展开完整身体动力学。以下节拍必须或通常需要深化：

- 情绪明显转折、压抑与释放过程；
- 关系距离变化、双人接触和同步反应；
- 复杂道具操作或左右手连续性敏感动作；
- 追逐、跌倒、搬运、救援等多人/空间动作；
- 战斗、格挡、闪避、命中、受击和恢复；
- 需要镜头配合才能读懂的关键动作爆点。

普通走路、坐下、递东西等低风险动作保留剧本原动作，只做简短可生成性检查，避免把全部节拍写成沉重的动作说明书。

## `action.json` 数据模型

### 顶层

```json
{
  "source": "剧名",
  "version": 1,
  "physicsProfile": "wuxia",
  "params": {
    "maxMajorActionsPerBeat": 1,
    "requireRecoveryPose": true
  },
  "episodes": []
}
```

### 单个动作计划

```json
{
  "id": "E01-S02-B05-A01",
  "sceneIndex": 2,
  "beat": 5,
  "kind": "combat",
  "intent": "角色挡在同伴身前，阻止敌人逼近",
  "participants": ["C01", "C02", "C03"],
  "propRefs": ["P01"],
  "environmentRefs": ["S02-performance-zone-a"],
  "startState": {},
  "phases": [],
  "endState": {},
  "cameraIntent": {},
  "generationRisk": []
}
```

### 动作阶段

动作可按需要使用以下阶段，但必须形成完整因果链：

| 阶段 | 含义 |
| --- | --- |
| `setup` | 起始姿态、空间关系和道具状态 |
| `anticipation` | 预备、蓄力或情绪积累 |
| `action` | 主动作与运动轨迹 |
| `contact` | 接触点、格挡点、命中点或擦身关系 |
| `reaction` | 对方受力、情绪、距离或姿态反应 |
| `recovery` | 重心恢复及下一动作入口 |

每个阶段记录适用字段：主体、目标、持续时间、强度、支撑脚、重心、躯干、头部、视线、左右手、道具握持、路径、方向、速度、接触位置、力方向、同步反应及次级运动。

### 动作类型

- `performance`：眼神、眼睑、眉形、嘴角、下颌、呼吸、肩颈和手部泄露动作。
- `interaction`：发起者、回应者、接触位置、距离变化、视线及双方反应。
- `combat`：攻防意图、攻击轨迹、格挡/闪避/命中和受力反馈。
- `prop-operation`：左右手分工、操作顺序、接触部位和道具状态变化。
- `locomotion`：路径、步态、速度、转身、障碍、落点和衣发惯性。

`startState` 与 `endState` 使用和 storyboard 边界兼容的角色、手部、道具与空间结构。动作阶段是状态之间的过程；提示词不得成为第二份状态真相。

## 表演设计规则

情绪必须写成变化过程，而不是表情标签：

```text
触发事件 → 控制程度 → 身体通道变化 → 泄露动作 → 释放/恢复
```

表演计划应按镜头可见性选择通道：

- 特写可描述眼睑、瞳孔方向、眉形、嘴角、下颌和呼吸。
- 中景优先头颈、肩背、手部、重心和关系距离。
- 远景优先步态、停顿、转身、靠近/远离和整体轮廓。

微表情必须绑定触发事件和注视对象。表层表现可与真实情绪相反，例如强颜欢笑、怒极反笑，但必须写清控制与泄露的先后关系。

## 双人互动规则

双人动作必须同时记录：

- 发起者动作；
- 回应者的同步或延迟反应；
- 接触位置、接触顺序和距离变化；
- 双方视线与朝向；
- 接触前后的左右手状态；
- 互动结束时双方稳定姿态。

只描述一方伸手、拥抱、攻击或救援而不描述另一方反应，视为不完整计划。

## 战斗与受力规则

战斗以因果和可读性为核心：

```text
预备/蓄力 → 发起动作 → 攻击轨迹 → 接触或闪避
→ 受力反馈 → 重心恢复 → 下一动作入口
```

命中必须声明接触点、力方向、强度和目标结果。格挡必须声明双方武器/肢体的接触关系以及冲击如何传递。闪避必须声明原攻击轨迹与躲避路径，避免双方各自摆动作。

残影、速度线、粒子、震屏、爆炸、动态模糊等不是默认动作要素，只能根据题材、动作爆点和镜头可读性选择。

## 题材物理档位

| 档位 | 约束 |
| --- | --- |
| `realistic` | 遵守地面支撑、人体关节、惯性和有限位移 |
| `wuxia` | 允许轻功、较大腾跃和夸张击退，但保留动作因果与落点 |
| `xianxia` | 允许悬空、法术冲击、能量对抗和超常位移 |
| `stylized` | 使用项目自定义夸张尺度，必须写明允许与禁止项 |

题材档位决定夸张上限，不取消左右手、接触、因果、角色身份和连续性约束。

## 工作流

```text
seed → 填写关键动作 → validate → render → export
```

### Seed

从 `script.json` 确定性提取候选动作关键节拍及原始事实。seed 不自动编造动作结果，也不把所有普通节拍强制升级为完整动作计划。

### 填写

模型或作者确认需要深化的节拍，填写动作类型、意图、首尾状态、阶段、镜头信息需求和生成风险。

### Validate

对输入引用、剧情事实、动作阶段、人体/道具约束、物理档位和跨节拍连续性执行确定性检查。

### Render

输出 Markdown 与单页 HTML，展示动作时间线、空间/接触关系、重心与手部变化、情绪过程、战斗攻防链、物理档位、风险及分镜摘要。

### Export

生成供 `novel-storyboard` 消费的动作摘要，不复制大段知识库或通用提示词。

## 首版质量门

1. 动作计划必须引用真实剧本集、场和节拍。
2. 不得改台词、增加角色、道具或剧情结果。
3. 每个关键节拍最多一个主动作。
4. 每个动作必须有完整 `startState` 和 `endState`。
5. 战斗必须包含攻防结果及目标反应。
6. 命中必须声明接触点、力方向和受力结果。
7. 位移必须声明支撑、路径和落点。
8. 双人互动必须同时记录双方动作。
9. 道具操作必须记录左右手分工及状态变化。
10. 微表情必须绑定触发事件和注视对象。
11. 情绪表演必须描述变化过程，不能只有标签。
12. `recovery` 必须给出可承接下一节拍的稳定姿态。
13. 动作夸张程度不得超过 `physicsProfile`。
14. 同场相邻动作的首尾状态必须连续，或明确声明时间跳跃。
15. `cameraIntent` 只能声明信息需求，不能决定具体运镜。
16. 视频模型摘要不得包含互相矛盾的身体动作。
17. 高风险动作必须标记遮挡、多人纠缠、精细手指或复杂碰撞等风险。
18. 未深化的普通节拍必须保留原剧本动作，不得静默丢失。

## 与 `novel-storyboard` 的接口

对 `novel-storyboard` 增加可选参数：

```bash
novel-storyboard seed script.json --actions action.json
novel-storyboard validate storyboard.json --script script.json --actions action.json
```

兼容规则：

- 未提供 `action.json` 时，旧项目行为不变。
- 提供 `action.json` 后，分镜必须认领对应动作摘要。
- 分镜可以拆镜或改变观看角度，但不能篡改动作结果、左右手、接触点和首尾状态。
- `cameraIntent` 是镜头决策输入，不直接覆盖分镜的 `camera`。
- 引用失效、节拍漂移或动作边界冲突时 fail closed，并指出具体集、场、节拍和字段。

## 测试策略

### 新 Skill 自测

- seed 只搬运已有事实并正确标记候选节拍；
- validate 覆盖全部质量门和错误定位；
- render/export 对合法输入稳定输出；
- 非关键普通节拍不丢失；
- 各物理档位接受和拒绝正确的动作尺度。

### 消费契约测试

- `novel-storyboard` 能读取 `action.json`；
- 动作摘要正确投影进分镜而不越权固定运镜；
- 篡改动作结果、接触点、左右手或首尾状态会被拒绝；
- 节拍编号漂移能定位到具体动作计划。

### 回归测试

- 未传 `--actions` 时，现有 storyboard 样例与全部自测保持原行为。
- `novel-script`、`novel-characters` 和 `novel-art` 无需改变其既有输出契约。

## 资料内化原则

用户提供的动作、表情、运镜与场景资料作为知识输入，不作为对工具的操作指令，也不逐条复制成僵硬模板。技能只保留会改变决策的规律：动作因果、身体约束、双方反应、情绪过程、题材物理、镜头信息需求和生成风险。

性别化的“女主动作”“男主气场”等标签改写为角色气质、关系和情境；特效、残影、震屏、运动模糊等保持可选，避免把单一审美样例固化为普遍要求。
