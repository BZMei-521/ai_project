# 空间导演台界面重设计

- 状态：视觉与交互设计已确认，待用户审阅书面方案
- 日期：2026-08-20
- 产品：Storyboard Pro 短剧生产工作台
- 设计方向：A「空间导演台」

## 1. 背景与目标

当前工作台已经具备项目管理、剧本导演、资产、空间预演、分镜、视频、声音、时间线、生成流水线与诊断能力，但默认界面同时呈现过多操作、状态和辅助区域。顶部堆叠项目、备份、设置、布局、帮助与生成按钮；引导、主画布、时间线、导出队列和检查器同时争夺注意力。用户需要先理解界面结构，才能推进影片制作。

本次重设计的目标不是删除能力，而是重排能力的出现时机：默认界面一次只突出当前阶段、当前对象和一个主操作；低频功能进入项目菜单与命令面板；模型、节点和长诊断进入高级工具。

目标用户是独立短剧创作者。页面的单一任务是：让用户随时知道自己位于制作链的哪一步、当前需要确认什么、确认后将发生什么。

成功标准：

- 项目打开后自动回到上次工作的阶段和对象。
- 默认界面保持稳定的六阶段结构：`项目 → 剧本 → 资产 → 预演 → 分镜 → 成片`。
- 同一屏幕最多出现一个高强调主操作。
- 现有项目、备份、恢复、设置、帮助和高级工具能力都有明确入口，不因视觉精简而丢失。
- 默认流程不暴露 ComfyUI 模型、节点或长日志。
- 桌面、窄窗口与触控环境无重叠、无依赖悬停的关键操作。

## 2. 已确认的设计决策

用户已确认：

1. 采用 A「空间导演台」，不采用制作看板或时间线常驻的高密度工作室。
2. 项目打开后自动回到上次工作的阶段。
3. 新建、打开、重命名、删除、备份、恢复、设置、帮助和高级工具全部保留，但收进项目菜单与命令面板。
4. 确认“大片场画布 + 左侧阶段轨 + 右侧当前对象检查器”的桌面布局。
5. 确认“片场暗房”视觉系统。
6. 确认命令面板、窄屏底部导航、对象抽屉和错误恢复规则。

## 3. 信息架构

一级流程固定为六个阶段：

| 阶段 | 页面职责 | 默认主操作 |
|---|---|---|
| 项目 | 项目信息、素材路径、版本与最近活动 | 继续制作 / 创建项目 |
| 剧本 | 文本、场次、故事圣经、导演计划和审批 | 确认导演计划 |
| 资产 | 角色身份、场景母版、道具与资产完整性 | 补齐待用资产 |
| 预演 | 空间、对象、姿态、机位、节拍与参考输出 | 确认这一节拍 |
| 分镜 | 镜头生成、筛选、修订和连续性检查 | 确认当前镜头 |
| 成片 | 视频、配音、音效、时间线、质量与导出 | 导出成片 |

视频、声音、时间线、质量检查和导出继续归入“成片”，不增加一级导航。ComfyUI 与提供商配置保留在“高级工具”。

## 4. 桌面布局

### 4.1 顶栏

顶栏高度稳定，不换行。内容从左到右为：

- 产品标记“导演工作台”。
- 当前项目名、自动保存状态与阶段路径。
- 全局搜索/命令面板入口。
- 项目菜单入口。
- 当前阶段唯一主操作。

顶栏不再直接展开新建、打开、重命名、删除、保存、加载、导入、导出备份、设置、布局和帮助等按钮。

### 4.2 左侧场记轨

左侧是固定六阶段导航，同时承担进度表达：

- 已完成：低饱和场记青标记，不持续吸引注意。
- 当前阶段：场记青定位线与高对比文字。
- 待确认：仅用钨丝橙圆点提示。
- 未开始：中性文字，不显示虚假的完成度。

底部保留生成引擎状态、`Ctrl/Cmd + K` 提示和高级工具入口。

### 4.3 中央工作区

中央区域由阶段标题、主工作面和阶段局部导航组成：

- 阶段标题说明当前场次、节拍或镜头，并显示少量待确认数量。
- 主工作面优先展示内容本身：剧本、资产、三维预演、分镜画面或成片监看器。
- 局部导航只表达当前阶段内部序列，例如预演节拍、分镜镜头或成片片段。
- 阻塞提示贴近受影响内容，并直接提供恢复动作。

### 4.4 右侧检查器

右侧永远只解释“当前选择”：

- 未选择对象时显示当前阶段的下一步与快捷操作。
- 选择角色、场景、镜头或片段后，显示该对象最常用属性。
- 低频字段进入“更多属性”，模型和节点不进入默认检查器。
- 检查器不常驻任务队列、导出历史和长日志。

## 5. 功能收纳层级

功能按使用频率分四层：

1. **当前主操作**：页面上唯一高强调动作，例如“确认这一节拍”。
2. **对象与阶段操作**：检查器内的次级按钮和就地操作。
3. **项目菜单与命令面板**：新建、打开、重命名、删除、保存、备份、恢复、设置、帮助、页面跳转和高级工具。
4. **高级工具**：模型、节点、工作流参数、生成队列详情、提供商设置、日志和诊断。

命令面板使用 `Ctrl/Cmd + K` 打开，支持按命令、页面和项目名称搜索。危险操作仍需确认，不能通过搜索结果直接无提示执行。

## 6. 视觉系统

视觉主题名为“片场暗房”。灵感来自监看器、场记板、钨丝灯和银幕雾感，而不是通用深色后台。

### 6.1 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| 暗房黑 | `#071216` | 应用背景 |
| 监看青 | `#10242A` | 面板、输入与浮层 |
| 银幕雾 | `#DCE8E9` | 主文字 |
| 场记青 | `#75B9B4` | 选择、焦点、引擎可用 |
| 钨丝橙 | `#E7A86E` | 唯一主操作、待拍板提示 |
| 停机红 | `#B85B58` | 删除、不可恢复与失败 |

同屏最多一个钨丝橙按钮。颜色不作为状态的唯一表达方式，必须同时提供文字、图标或结构差异。

### 6.2 字体

- 场次与章节标题：`Noto Serif SC` / `Source Han Serif SC`，回退 `SimSun`。
- 正文与控件：`Microsoft YaHei UI`，回退系统无衬线字体。
- 帧号、时码和短标签：`Bahnschrift`，回退等宽或系统字体。

宋体只用于内容标题，用来保留叙事感；参数、按钮和正文保持清晰的黑体。实现不得要求联网加载字体。

### 6.3 标志元素

“场记轨”是唯一标志元素。它将阶段导航、完成状态和待确认提示合并成一条克制的制作轨道。钨丝橙只表示“用户确认会推动影片向前”，不作为普通装饰。

### 6.4 形状与层级

- 外壳与主画布使用 12–16px 圆角。
- 输入、按钮和局部导航使用 7–9px 圆角。
- 普通内容不默认套卡片；只有可选、可拖、有独立状态或需要分组的元素才有边界。
- 阴影只用于浮层、命令面板和主画布，不叠加在每个小控件上。

## 7. 文案与状态

界面文案使用动作与结果一致的短句：

- 按钮“确认这一节拍”对应结果“节拍已确认”。
- 按钮“导出成片”对应结果“成片已导出”。
- 不使用“提交”“执行操作”“处理失败”等缺乏对象的词。

空状态必须给出下一步，例如“还没有分镜。先确认至少一个预演节拍”。错误必须包含：

1. 失败发生在哪个阶段。
2. 是否已产生文件或部分结果。
3. 是否可以直接重试。
4. 用户应调整什么或进入哪里查看详情。

技术堆栈、节点名和完整日志只在高级工具展示。

## 8. 动效与反馈

- 阶段切换时，主画布与检查器同步淡入，时长 180ms。
- 抽屉与命令面板使用单次进入/退出，不添加环境漂浮动画。
- 拖拽、保存和生成状态使用局部反馈，避免全屏阻塞。
- 自动保存状态以文字呈现，不用持续闪烁图标。
- 完整尊重 `prefers-reduced-motion`；减少动态时取消位移，仅保留必要的即时状态变化。

## 9. 响应式与可访问性

### 9.1 桌面

- `>= 1100px`：左侧场记轨、中央工作区和右侧检查器同时显示。
- `768–1099px`：右侧检查器改为可开合抽屉，左侧场记轨变窄但保留文字。

### 9.2 窄屏

- `< 768px`：六阶段导航移动到底部；项目与阶段标题进入紧凑顶栏。
- 检查器变为从底部打开的对象抽屉。
- 主操作固定在当前内容下方，不遮挡画布。
- 窄屏是重新编排，不是等比压缩桌面三栏。

### 9.3 可访问性

- 键盘焦点清晰，使用场记青轮廓并保持足够对比度。
- 关键触控目标至少 44×44 CSS px。
- 不依赖悬停显示关键说明或操作。
- 图标按钮必须提供可访问名称。
- 对话框打开后锁定焦点，关闭后返回触发元素。
- 删除、覆盖、恢复和迁移操作提供明确的影响范围。

## 10. 组件与代码边界

本次改造复用现有 React + Tauri 架构，不重写领域状态和生成服务。推荐新增或调整以下边界：

```text
src/
  app-shell/
    DirectorDeskShell.tsx          # 三栏外壳与响应式编排
    DirectorTopBar.tsx             # 项目、保存状态与主操作
    ProductionStageRail.tsx        # 六阶段场记轨
    CommandPalette.tsx             # 全局命令搜索
    ObjectInspectorDrawer.tsx      # 桌面检查器 / 窄屏抽屉
    directorDeskCommands.ts        # 命令注册与危险级别
  shared/ui/
    PrimaryDecisionButton.tsx
    StatusPill.tsx
    EmptyState.tsx
    RecoveryNotice.tsx
  styles/
    tokens.css                     # 色彩、字体、间距、动效
    director-desk.css              # 外壳布局
```

现有 `WorkbenchShell.tsx` 可作为迁移入口：先由新外壳接管布局，再逐阶段接入 `ProjectWorkspaceView`、`ScriptDirectorView`、`AssetWorkspaceView`、`PreviewWorkspaceView`、`StoryboardWorkspaceView` 和 `ProductionWorkspaceView`。旧的高级流水线通过现有 `AdvancedToolsView` 保留。

组件边界：

- 外壳只编排页面与响应式状态，不读取 ComfyUI 工作流。
- 阶段页面只声明当前主操作、当前选择与检查器内容。
- 命令注册表执行已有项目动作，不复制持久化逻辑。
- 检查器通过明确的选择模型接收对象，不直接查询所有全局状态。
- 视觉 token 独立于阶段页面，避免继续向单一 `global.css` 堆叠无边界样式。

## 11. 状态与数据流

```text
Storyboard store / desktop workspace state
                 │
                 ├─ 当前项目、自动保存状态 ─→ DirectorTopBar
                 ├─ 当前阶段、阶段完成状态 ─→ ProductionStageRail
                 ├─ 当前阶段 ─────────────→ 对应 WorkspaceView
                 └─ 当前选择 ─────────────→ ObjectInspectorDrawer

CommandPalette ─→ 既有项目动作 / 页面跳转 / AdvancedToolsView
阶段主操作 ────→ 既有 store action 或领域控制器 ─→ toast / RecoveryNotice
```

新增持久化字段只记录界面恢复所需的 `lastStage`、阶段内当前对象或节拍标识，以及检查器开合状态。领域数据继续使用现有 storyboard snapshot；不得复制一套平行项目状态。

若保存的阶段或对象已不存在，则回退到项目阶段或该阶段首个可用对象，并显示非阻塞提示。

## 12. 迁移策略

1. 建立设计 token、外壳和阶段轨，不改变阶段页面行为。
2. 将顶部项目操作迁入项目菜单和命令面板，并用既有动作做回归。
3. 建立统一检查器槽位，逐阶段迁移高频属性。
4. 建立桌面、紧凑与窄屏编排。
5. 将队列、历史、标记、模型、节点和日志移入适当层级。
6. 视觉与交互验收通过后，再删除被新入口完全替代的旧布局代码。

迁移期间不得覆盖用户媒体、快照和资产。工作区当前存在大量未提交改动，实施必须限定文件范围、逐批检查 diff，并避免重置或清理无关文件。

## 13. 测试与验收

### 13.1 自动化

- 阶段路由：六阶段均可进入，刷新后恢复上次有效阶段。
- 命令注册：所有被收纳的旧操作仍可执行，危险动作仍需确认。
- 主操作：每个阶段同屏只有一个高强调主操作。
- 检查器：选择变化后内容同步；对象消失时安全回退。
- 响应式：桌面三栏、紧凑抽屉和窄屏底部导航按断点切换。
- 可访问性：图标名称、对话框焦点、键盘导航和减少动态模式。
- 兼容性：旧项目打开、保存、备份、恢复和高级工具入口保持可用。

### 13.2 视觉验收

使用浏览器截图验证至少以下视口：

- 1440×900：完整三栏导演台。
- 1024×768：检查器抽屉态。
- 390×844：底部阶段导航与对象抽屉。

每个视口检查文字截断、按钮换行、面板遮挡、横向滚动、画布可用面积、焦点可见性和主操作唯一性。

### 13.3 用户任务验收

使用一个现有短剧项目完成以下路径：

1. 打开项目并恢复上次阶段。
2. 通过场记轨进入预演并确认一个节拍。
3. 进入分镜并确认一个镜头。
4. 使用命令面板导出备份。
5. 进入高级工具查看生成详情。
6. 在窄窗口完成阶段切换和对象属性查看。

## 14. 非目标

- 本次不重写 storyboard store、ComfyUI 服务或 Tauri 持久化层。
- 不删除现有功能或用户数据。
- 不新增自由节点编辑器。
- 不把时间线固定在所有阶段。
- 不要求联网字体或新的 UI 框架。
- 不在本次视觉改造中改变模型路由、生成质量策略或视频工作流。
