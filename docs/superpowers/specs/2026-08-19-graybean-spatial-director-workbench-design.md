# 灰豆式空间导演工作台设计

- 状态：已确认设计，待实施计划
- 日期：2026-08-19
- 目标：将现有信息密集、职责耦合的故事板界面改造成灰豆式轻量生产引擎，并以可用的轻量三维预演解决场景、姿态与机位连续性。

## 1. 背景与问题

当前项目的生成能力较完整，但用户需要直接理解 ComfyUI、模型、节点、队列、质量检查和多层诊断信息。主要界面与服务职责过度集中：`ComfyPipelinePanel.tsx` 约 1.8 万行，`comfyService.ts` 约 3.3 万行，样式也集中在单一大文件中。结果是首页信息过载，生成能力和产品流程混在一起，难以维护。

灰豆 AI 光影引擎提供了更合适的产品化参考：故事先进入导演流程，再形成角色、场景、道具、连续性规则和镜头计划，最后进入图片、视频、声音和时间线。项目已有 AI 导演与 360° 场景设计，本次将其转化为默认工作台，同时保留现有生成引擎作为底层执行器。

## 2. 用户目标

用户打开项目后可以沿着一条清晰的生产链完成短片：

`项目 → 剧本 → 资产 → 预演 → 分镜 → 成片`

视频、配音、音效、时间线、质量检查和导出归入“成片”，不再占用一级导航。用户不需要先理解模型或节点；只有进入“高级工具”时才看到旧编辑器、ComfyUI 参数、任务详情、日志和诊断信息。

## 3. 产品结构

默认页面是“空间导演台”，采用三块稳定结构：

- 左侧：六阶段生产导航。
- 中央：当前阶段工作区；在“预演”阶段为主要的 360° / 三维空间视图。
- 右侧：当前对象与当前节拍检查器，只显示与选择相关的属性。

顶部只显示项目名、保存状态、引擎状态和当前阶段的一个主操作。任务中心以 `等待、运行、需处理、完成、失败` 五种简洁状态呈现，节点、模型、长日志和诊断信息隐藏在“高级工具”。

各阶段职责如下：

- 项目：创建、打开、备份、恢复和项目切换。
- 剧本：读取当前小说或外部文本，生成故事圣经、角色/场景清单和导演计划，并提供审批门。
- 资产：管理角色身份包、360° 场景母版和道具。
- 预演：修正空间、摆放代理对象、调整姿态和相机，并保存节拍。
- 分镜：消费预演参考输出，生成、筛选和修订镜头。
- 成片：生成视频、配音和音效，装配时间线，执行质量检查并导出。

## 4. 轻量三维预演

“预演”阶段使用 Three.js，并承担空间事实，不承担最终美术外观。

### 4.1 场景与对象

- 2:1 equirectangular 全景母版作为环境背景。
- 自动估计地面、深度和主要地标，生成初始代理空间。
- 用户可修正地面高度、障碍物位置、入口/出口和可行走区域。
- 角色使用可摆姿势的人形骨架代理；动物与道具使用简化代理模型。
- 每个对象持久化 `position / rotation / scale`，并记录对象类型、空间锚点和可见性。

### 4.2 操作与节拍

- 选择、移动、旋转、缩放工具；支持拖拽走位、吸附、撤销/重做。
- 透视与俯视模式切换，显示/隐藏对象和冲突提示。
- 相机保存位置、目标点、FOV、景别、安全框和方向锚点。
- 每个剧情节拍保存对象变换、骨架姿态、遮挡关系和相机计划。
- 自动初始化只能产生草稿；人工确认前不得启动正式分镜生成。

### 4.3 参考输出

每个已确认节拍可确定性导出：

- 彩色预演图
- 深度图
- 法线图
- 角色/道具遮罩
- 骨架姿态图
- 相机与空间参数 JSON

这些输出进入分镜生成适配器，作为空间与姿态约束。ComfyUI 负责外观生成，不再重新猜测人物站位、遮挡和镜头空间。

## 5. 代码架构

```text
src/
  app-shell/              # 导航、项目切换、全局状态
  features/
    project/
    script-director/
    assets/
    spatial-preview/
    storyboard/
    production/
    advanced-tools/
  domains/
    project/
    director/
    spatial-scene/
    shot/
    generation/
  services/
    persistence/
    generation-providers/
    media/
  shared/
    ui/
    hooks/
    types/
```

边界约束：

- 页面组件目标不超过 300 行，领域服务目标不超过 500 行。
- React 组件不直接拼装 ComfyUI 工作流。
- Three.js 场景状态与 React 界面状态分离。
- 模型节点、参数绑定和队列协议集中在生成适配器。
- 领域层不依赖 ComfyUI、Tauri 或具体模型名称。
- 每个模块只公开明确入口，禁止跨目录读取内部文件。
- `ComfyPipelinePanel.tsx` 按页面、控制器和小型控件拆分。
- `comfyService.ts` 按角色、场景、分镜、视频、质量检查和基础客户端拆分。
- 旧模块先通过适配器接入新界面，迁移完一个职责后再删除对应旧分支。

## 6. 旧项目兼容

旧项目打开时执行版本化迁移：

1. 读取旧快照，不修改原文件。
2. 为缺失字段补默认值，包括场景空间、对象变换、节拍和相机计划。
3. 首次写入新版本快照前生成带时间戳的备份。
4. 保留旧字段兼容周期；新界面只写新规范字段。
5. 高级工具支持回退或导出旧格式。
6. 迁移失败时原项目保持不变，并显示可操作错误。

删除遵循引用证明：先扫描静态入口、导入、动态加载和构建路径；替代模块、UI、持久化和回归测试全部通过后才删除。任何删除都记录原路径、替代模块和验证命令。不删除用户媒体、角色图、视频、项目快照，不执行 `reset`、`clean` 或批量清理未跟踪文件。

## 7. 状态与错误

长任务进入统一任务中心。主界面只显示五种状态；错误必须说明失败阶段、文件是否产生、是否可重试以及恢复动作。节点级日志和详细诊断只在高级工具展开。

## 8. 验收与测试

- 单元：空间坐标、相机参数、节拍快照、迁移和任务状态机。
- 集成：旧项目打开、备份回退、预演参考进入分镜、生成结果回写。
- 视觉：桌面和窄屏截图，检查文字溢出、控件遮挡、三维画布非空和交互状态。
- 工作流回归：角色身份、全景、分镜、H3 视频、声音、时间线和导出。

首版必须满足：

- 默认界面不显示 ComfyUI 节点、模型清单或长诊断信息。
- 用户可在六个阶段完成一个短片项目。
- 预演场景可保存并重新打开，物体、姿态和相机不漂移。
- 五类参考输出和参数 JSON 可复现。
- 旧项目可无损打开，迁移失败不改写原文件。
- 新模块没有上万行文件，旧巨型文件随迁移实际下降。
- 每批删除都有替代路径和回归证据。
- 桌面与窄屏无重叠，三维画布经截图与像素检查确认非空且可交互。

## 9. 非目标

- 本阶段不接入云端模型、账号、计费或登录。
- 不复制灰豆代码、资源、模型路由或服务地址。
- 不实现自由节点画布。
- 不一次性重写所有旧文件。
- 不要求所有场景生成 360° 全景。
- 不自动删除或覆盖已有资产、视频和项目快照。
