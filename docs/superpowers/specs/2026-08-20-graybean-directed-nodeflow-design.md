# 灰豆式导演主流程节点工作台设计

日期：2026-08-20  
状态：待用户确认后实施

## 目标

将当前“六阶段页面 + 大量旧面板”的入口改为一张固定的导演主流程画布。用户打开项目后直接看到从剧本到成片的主链路，通过节点状态和连线理解项目进度；节点参数在右侧检查器中编辑，复杂能力收进节点的高级分支，不在首屏铺开。

## 交互结构

```text
┌──────────┬──────────────────────────────┬──────────────┐
│ 工具栏   │  主流程节点画布               │ 当前节点检查器 │
│          │ 剧本 → 角色 → 空间 → 分镜 → 成片 │ 参数/运行/输出 │
└──────────┴──────────────────────────────┴──────────────┘
```

- 左侧窄工具栏：选择、添加节点、框选、运行/暂停。
- 中央画布：固定左到右主链，节点之间用有方向连线表达数据流。
- 右侧检查器：只显示当前选中节点的参数、运行按钮、输出摘要和错误信息。
- 节点可展开局部分支，但默认不展开；分支不能改变主链的阅读顺序。
- 主链节点：剧本、角色资产、空间预演、分镜、成片。
- 项目输入作为隐含上下文，不单独占用主流程卡位；项目设置放在顶部项目菜单。

## 节点状态

每个节点显示统一状态：未开始、等待上游、运行中、已完成、失败。状态只由现有任务/持久化数据推导，不新增第二套任务系统。运行当前节点时保留现有 provider、Comfy、Tauri/Web bridge 和快照字段。

## 数据边界

- 节点画布只保存布局、选中节点、折叠状态和连线视图状态。
- 剧本、角色、空间场景、分镜、视频和音频仍使用现有 store/schema。
- 右侧检查器调用现有动作，不复制生成逻辑。
- 保存/加载继续经过当前迁移和桌面备份链。
- 旧六阶段导航不删除；作为兼容入口保留在“更多工具/传统视图”中，默认不渲染旧面板。

## 范围控制

本轮只实现：主流程壳、节点卡片、连线、选中态、检查器插槽、状态映射、响应式布局和持久化的视图状态。暂不实现自由拖拽连线编辑器、节点市场、实时协同和新的生成后端。

## 验收标准

1. 首屏不出现旧引导、旧时间轴或大面积诊断面板。
2. 五个主节点和四条主连线在 1280px 桌面视口可见。
3. 点击节点只更新右侧检查器，不改变主链布局。
4. 运行中、完成、失败状态与现有任务状态一致。
5. 刷新后节点选中态、折叠态和画布视图状态可恢复。
6. 现有构建、迁移、空间预览和生成契约检查继续通过。
7. 390px 视口下画布可横向滚动，检查器改为底部抽屉，不发生内容覆盖。

## 视觉方向

采用深色工作台底色、细网格、低饱和青绿色连线和橙色运行动作。节点卡片信息密度低于当前旧面板，状态优先于说明文字；唯一强调元素是从左到右的导演主链。
