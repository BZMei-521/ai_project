# StoryboardPro 链式一镜到底视频设计

日期：2026-08-10

## 目标

将当前六个独立 Wan I2V 片段改为一个视觉上完全连续、无切镜、无溶解、无隐藏剪辑的长镜头。最终视频约 6 秒，输出 24 FPS。沈砚与江岚在整个镜头中保持恰好两人，脸、发型、服装、体型与物种不漂移。

## 已确认的产品语义

- 只使用第一张分镜作为视觉起始帧。
- 第 2–6 张分镜仅提供剧情动作和节奏提示，不再控制构图或机位。
- 第 N 段必须使用第 N-1 段的真实末帧作为唯一视觉起点。
- 全程使用同侧连续机位；禁止反打、跳轴、突然变焦、场景替换和重新构图。
- 最终拼接删除重复边界帧，不使用交叉溶解、强制光流变形或遮挡藏切。

## 生成架构

### 链式段落

1. 河边建立：从现有第一张最终分镜开始，人物产生轻微自然动作。
2. 开始交流：以上一段末帧继续，江岚转头并开始说话，镜头缓慢向前跟随。
3. 边走边说：继续同一运动方向，江岚表达思考，沈砚观察桥边。
4. 察觉异常：沈砚轻微减速、点头并抬手示意，镜头不换侧。
5. 沿河慢走：两人保持连续步态和接地关系，镜头稳定跟拍。
6. 桥边停步：两人自然减速，江岚观察水边，沈砚转身警戒。

每段使用 Wan 2.1 I2V、832×480、17 帧、16 FPS、20 steps、CFG 5、`uni_pc`。后续段落的起始图片由上一段末帧提取并上传到 ComfyUI。随机种子按段固定，失败重试只改变当前段种子。

## 数据流

```text
第一张分镜 → 生成段1 → 提取末帧1
末帧1 → 生成段2 → 提取末帧2
末帧2 → 生成段3 → 提取末帧3
末帧3 → 生成段4 → 提取末帧4
末帧4 → 生成段5 → 提取末帧5
末帧5 → 生成段6
段1 + 段2去首帧 + … + 段6去首帧 → 原生连续版 → 24 FPS交付版
```

## 拼接规则

- 段 1 保留全部 17 帧。
- 段 2–6 删除第 1 帧后再拼接，每段贡献 16 帧。
- 原生总帧数为 `17 + 5 × 16 = 97` 帧，16 FPS 时长约 6.0625 秒。
- 统一完成拼接后再补帧到 24 FPS。
- 不在段落边界应用 `xfade`。

## 连续性质量门槛

每段完成后、下一段开始前执行以下检查：

1. ComfyUI 状态必须为 success，输出必须是 H.264 MP4。
2. 输出必须为 832×480、16 FPS、17 帧。
3. 末帧中必须恰好有沈砚与江岚两人，无背景重复人物。
4. 两人的脸型、发型轮廓、服装结构和主色不得明显改变。
5. 不允许洋红/绿色块状色漂、曝光突变、场景替换或肢体严重变形。
6. 下一段使用的上传图片 SHA-256 必须等于上一段提取末帧的 SHA-256。

任一段失败时停止链条，只重试失败段；通过后才允许继续生成后续段落。

## 边界验收

- 对每个边界比较上一段末帧与下一段起始输入，文件哈希必须一致。
- 拼接后的五个边界不得出现额外帧、重复帧、溶解帧或黑帧。
- 使用 FFmpeg scene score 检查最终视频；边界不应出现独立生成版本中 0.42–0.56 的单帧峰值。
- 提取 97 帧接触表，人工检查人数、身份、衣着、环境与动作方向。

## 失败处理

- Comfy 节点错误或显存不足：停止当前段，保留已完成报告，卸载模型后仅重试当前段。
- 身份或人数漂移：更换当前段种子并收紧动作幅度；不得沿用失败末帧。
- 色漂：更换当前段种子；仍失败则降低动作描述复杂度。
- 连续两次失败：缩短当前段动作，不改变已经通过的前序段。
- 三次失败：停止自动链条并报告具体段落，不继续污染后续生成。

## 实现范围

- 新增可重复运行的链式长镜头基准脚本。
- 新增段落报告，记录输入帧、输出视频、末帧哈希、种子、耗时与状态。
- 新增无转场、去重复首帧的拼接逻辑。
- 生成并验收当前六段河边长镜头。

本阶段不包含对白口型、配音、逐帧 FaceDetailer、RIFE 插件安装、多人分层模式或新视频模型下载。

## 测试

- 契约测试：六段必须串行生成，段 2–6 的输入来自前段末帧。
- 契约测试：拼接逻辑保留段 1 全帧并删除段 2–6 首帧。
- 集成测试：真实 ComfyUI 完成六段链条并生成 JSON 证据报告。
- 媒体验证：FFprobe 检查最终编码、尺寸、帧率、帧数和时长。
- 视觉验收：每段首、中、尾帧和最终 97 帧接触表。
