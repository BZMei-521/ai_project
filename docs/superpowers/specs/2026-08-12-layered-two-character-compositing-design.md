# 分层双人物合成验证设计

日期：2026-08-12  
状态：已通过对话设计评审，待用户书面评审

## 1. 目标与范围

本阶段验证“背景、沈砚、江岚分别生成，再受控合成并局部融合”的双人物分镜方案，优先解决跨镜头身份不一致。第一轮仅制作一张独立验证样片，不接入 StoryboardPro，也不生成视频。

验证镜头沿用当前河边首帧的 1152×640 画布、机位、石板落脚面、夕阳方向和人物相对位置。沈砚与江岚相对站立、互相注视，不牵手、不拥抱、没有身体接触。第一失败门槛是身份一致性：任一角色的脸、发型或服装主体明显偏离已确认角色资产，候选立即失败，不进入融合质量验收。

本阶段不包括：多人接触动作、批量分镜、视频动画、StoryboardPro UI 接入、MiniMax H3 本地部署、角色 LoRA 训练，以及无关工作区重构。

## 2. 选择的方案

采用独立人物分层合成：

1. 从当前批准首帧移除两名人物，建立固定空河景。
2. 根据各自角色资产和各自姿态，分别生成沈砚、江岚。
3. 使用 BiRefNet 分别提取透明人物和遮罩。
4. 按冻结的画布坐标、身高、前后层级和视线目标合成。
5. 只修复人物边缘、脚底接触、局部遮挡和环境反光。
6. 保护主脸、主要发型轮廓和服装主体，不允许最终融合阶段重绘。

该方案优先于“双人一次生成”，因为角色失败可以独立重做，不会使背景和另一名已通过角色作废；也优先于“匿名双人底稿再换脸”，因为后者容易在身份替换时改变头身比和服装结构。

## 3. 输入与固定资源

### 3.1 母版首帧

母版为：

`C:/Users/Administrator/AppData/Local/Comfy-Desktop/ComfyUI-Shared/output/Storyboard/河边远景建立_klein_ref_00006_.png`

实现开始时必须记录母版的绝对路径、尺寸和 SHA-256。禁止用网上下载的近似河边图片替代母版。空景应从母版派生，以保留相同的机位、透视、光源、色板与石板纹理。

### 3.2 角色生成包

沈砚和江岚各自使用隔离的角色生成包：

- 一张已确认的清晰主脸参考，作为唯一脸部身份来源；
- 一张已确认的正面全身参考，用于身材、服装和关键配饰；
- 可选的侧面或背面参考，只补充发型与服装结构，不竞争主脸身份；
- 固定角色描述，逐字复用脸型、五官、发型、服装主色、材质和配饰；
- 单人姿态约束、画布落点、目标身高与视线目标；
- 与母版一致的环境光描述。

角色参考缺失或未确认时，流程必须在生成前失败，不能降级为纯提示词猜测。

### 3.3 已保存的参考工作流

参考资料位于 `references/layered-compositing/`，包括：

- ComfyUI 核心 BiRefNet 去背景模板；
- ComfyUI 核心 SAM3 图像分割模板；
- ComfyUI 核心 SDPose 多人姿态模板；
- ComfyUI 核心 Depth Anything 3 模板；
- MiniMax H3 官方 T2V/R2V 模板与提示词指南。

MiniMax H3 仅作为后续视频参考，不属于本样片的运行依赖。

## 4. 组件边界

### 4.1 空景生成器

输入母版及双人物移除遮罩，输出固定空景。它只能填补人物原占据区域，不得改变画布尺寸、机位、河岸轮廓、树木位置、石板透视、夕阳方向或整体色板。空景一经人工确认即冻结，后续人物失败不得触发空景重做。

### 4.2 姿态与布局合同

从母版提取双人姿态和可验证的布局数据，再拆成两个单人合同。每个合同至少记录：

- 人物标识；
- 头顶和左右脚底的画布坐标；
- 目标人物像素高度及容差；
- 身体朝向和视线目标；
- 前后层级；
- 允许占据的画布边界；
- 与另一角色的最小间距。

第一轮不含身体接触，因此两个可见人物遮罩不得发生主体交叠；发丝或衣摆的少量软边重合不算主体交叠。

### 4.3 单人物生成器

两个角色严格串行、独立生成，使用各自角色生成包。输出必须是全身完整人物，头顶和双脚均在画布内。推荐使用便于抠图的中性背景，但中性背景不得改变来自河边母版的光线方向描述。

生成器保存原图、使用的参考资源哈希、提示词、负向约束、种子、模型和工作流版本。候选不通过时，只增加该角色的新候选，不覆盖已通过候选。

### 4.4 人物抠图器

首选 ComfyUI 核心 BiRefNet，分别输出透明 PNG 和灰度遮罩。SAM3 可用于修复 BiRefNet 对发丝、袖口或长裙的误分割，但不能替代主抠图结果而不留记录。

遮罩必须覆盖完整头发、身体、服装和双脚，同时排除原生成背景。流程应检查遮罩非空、连通区域合理、头脚未截断、透明 PNG 尺寸与母版一致。原始遮罩和修订遮罩都必须保留。

### 4.5 确定性合成器

合成器不调用生成模型。它按布局合同完成缩放、平移、层级、alpha 合成、环境色采样与基础阴影，输出“未修复合成图”。同一输入和参数必须得到相同结果。

### 4.6 局部融合器

局部融合器只接收允许修改遮罩，覆盖：

- 发丝最外缘；
- 衣物外缘；
- 双脚与石板接触区域；
- 接触阴影与石板局部遮挡；
- 人物边缘的低强度环境反光。

主脸、发型主体、服装主体和关键配饰形成硬保护区。局部融合不得使用全画面高强度重绘。

IC-Light 背景条件重打光是可选实验步骤。只有在输出通过身份保护检查时才可采用；如果它改变脸部结构、发型主体或服装图案，必须回退到确定性的亮度、色温、色阶和阴影匹配。安装 IC-Light 节点或下载权重属于单独批准的大型依赖操作，不在本设计文档提交时执行。

## 5. 数据流与产物

单次运行使用独立目录，至少保存：

1. 母版副本或不可变引用及哈希；
2. 空景及人物移除遮罩；
3. 沈砚原始候选、透明 PNG、原始遮罩、修订遮罩；
4. 江岚原始候选、透明 PNG、原始遮罩、修订遮罩；
5. 姿态和布局合同；
6. 未修复合成图；
7. 允许修改遮罩与身份保护遮罩；
8. 最终融合图；
9. 保护区修复前后差异图；
10. 模型、工作流、参考图、提示词、种子、参数和文件哈希清单；
11. 分阶段验收状态和人工评审记录。

已通过的空景或人物资产采用不可变版本标识。后续阶段不得原地覆盖它们。

## 6. 光照与消除“贴纸感”

母版的光照合同固定为：画面右后方的暖色夕阳作为主光，画面左前方为柔和环境补光，人物阴影投向左前方。具体强度和色温应从母版采样，而不是凭提示词重新解释。

人物合成分为以下视觉层：

1. 固定空景；
2. 人物环境反光与边缘色层；
3. 沈砚与江岚透明人物层；
4. 脚底压暗、软接触阴影和石板遮挡层；
5. 受限局部融合层。

“贴纸感”的判定重点是白边或黑边、锯齿、脚底漂浮、阴影方向错误、人物亮度/色温明显脱离背景、石板与脚部缺少接触遮挡。处理这些问题不得以重绘身份区域为代价。

## 7. 验收与失败策略

验收必须按顺序进行，前一关失败时不得用后一关的高质量掩盖失败：

### 7.1 身份门禁

- 画面中恰好有沈砚、江岚两人；
- 主脸能明确对应各自已确认主脸参考；
- 发型轮廓和颜色一致；
- 服装主色、主体结构和关键配饰一致；
- 不串脸、不换装、不新增兽族特征。

任一角色失败，只拒绝该角色候选。

### 7.2 构图门禁

- 两人全身完整且没有裁脚；
- 脚底落点、高度、前后层级在布局合同容差内；
- 两人相对站立、互相注视；
- 无身体接触、无主体遮罩重叠；
- 人物数量没有增加、复制或融合。

### 7.3 融合门禁

- 无明显抠图边缘、透明洞、锯齿或背景残留；
- 双脚与石板有可信接触关系；
- 阴影方向、软硬和环境色与母版一致；
- 人物没有明显漂浮或贴纸感。

### 7.4 身份保护门禁

局部融合前后对身份保护区计算像素差异并生成可视差异图。实现计划必须定义固定、可测试的差异指标和阈值；阈值应由角色参考与无修改基线校准，而不是在运行后为了通过某个候选而调整。超过阈值时拒绝最终融合结果并保留未修复合成图。

### 7.5 人工最终验收

人工评审同时查看角色参考、人物原图、透明人物、未修复合成、最终融合和保护区差异图。最终状态只能是 `accepted` 或 `rejected`，技术流程完成不能自动等同于视觉接受。

## 8. 错误处理与可恢复性

- 角色资源、母版或必要工作流缺失：排队前失败。
- 空景改变关键几何或光线：拒绝空景，人物阶段不运行。
- 单人物生成失败：保留其他已通过资产，只重试失败角色。
- 抠图失败：保留原人物候选，重做或修订遮罩。
- 合成合同越界：确定性失败，不进入 AI 融合。
- IC-Light 不可用或身份漂移：自动退回确定性色彩与阴影匹配；不把在线付费节点作为隐式兜底。
- 最终融合失败：保留未修复合成及全部诊断产物，禁止覆盖上一版已通过资产。
- 所有外部调用、模型下载和付费 API 必须显式记录；未获授权时不得自动触发。

## 9. 测试策略

实现阶段采用从失败到通过的契约测试，至少覆盖：

- 母版路径、尺寸和哈希记录；
- 两个角色生成包的隔离与必需字段；
- 布局合同拆分及坐标越界拒绝；
- BiRefNet 遮罩非空、尺寸、头脚完整和 alpha 输出；
- 角色 A 失败不会删除角色 B 或空景；
- 确定性合成可重复；
- 允许修改遮罩与身份保护遮罩不发生非法重叠；
- 保护区被篡改时验收失败；
- 最终状态需要人工接受，不能由技术完成自动接受；
- 所有产物、参数和哈希可追溯。

实时 ComfyUI 测试严格串行。先使用小尺寸或低成本预检验证图结构和节点库存，再运行一张 1152×640 正式候选；预检结果不得冒充正式样片。

## 10. 实施顺序与停止条件

实施顺序为：资源预检 → 空景 → 姿态/布局合同 → 沈砚 → 沈砚身份确认 → 江岚 → 江岚身份确认 → BiRefNet 抠图 → 确定性合成 → 局部融合 → 分层验收。

本阶段在以下任一条件发生时停止，不扩展到 StoryboardPro：

- 角色资产尚未确认；
- 三次受控候选仍无法通过某个角色的身份门禁；
- 空景无法保持母版关键几何；
- 最终融合只能通过修改主脸或服装主体来消除贴纸感；
- 需要未经批准的大模型下载、付费 API 或新增第三方节点。

只有独立样片通过身份、构图、融合和人工最终验收后，才另行设计 StoryboardPro 单镜头接入和后续接触动作。

## 11. 工作区与版本控制边界

本功能使用新的、明确命名的工作流、运行脚本、契约测试和样片日志目录，不混入旧的全身上下文遮罩实验。旧实验文件、恢复副本、重复日志和临时文件仅列入后续保守清理清单；删除前必须展示精确路径、分类、占用空间和可恢复性，并再次取得用户批准。

设计文档提交只包含本文件。当前工作区其他已修改或未跟踪文件均视为既有用户工作，不暂存、不覆盖、不丢弃。
