# Klein 零样本 / LoRA 双轨人物一致性发布设计

日期：2026-08-09  
状态：待用户确认

## 1. 决策与目标

人物一致性发布采用两条相互独立、证据不可混用的生产轨道：

1. `zero_shot_multi_reference`：使用 FLUX.2 Klein 4B 和版本化角色身份包进行零样本多参考生成。只要通过严格的八镜头自动基准，即可成为本机默认生产基线。
2. `lora_augmented`：在相同身份包与基础模型上加载已验证的角色 LoRA，作为长线主角和高价值角色的增强层。

本次设计不是降低现有 LoRA 门禁，而是补充一个真实可验证的零样本发布门禁。零样本证据不能证明 LoRA 可用，LoRA 证据也不能在移除 LoRA 后自动降级为零样本证据。

目标硬件为 RTX 5070 Ti 16GB、约 48GB 系统内存、ComfyUI Desktop。已完成的真实运行表明，官方 `flux-2-klein-4b-fp8.safetensors` 能在该机器上串行完成八镜头生成，因此通过正式评分后，Klein 可成为该硬件配置的默认人物提供器。Qwen Image Edit 2511 继续保留为可选/卸载运行方案，不作为本机默认基线。

## 2. 范围与非目标

本次包含：证据结构、基准命令、可信评分器接口、身份参考绑定、发布门禁、失效规则、生产选择和 UI 状态。

本次不包含：自动训练 LoRA、云端训练调度、逐帧视频一致性、口型同步，也不把人工主观勾选当作可发布证据。

## 3. 领域模型

新增生成模式：

```ts
type CharacterGenerationMode =
  | "zero_shot_multi_reference"
  | "lora_augmented";
```

新增统一的 `CharacterGenerationEvidence`，至少绑定以下不可变信息：

- `generationMode`
- 人物提供器 ID、提供器版本和精确基础模型文件名
- 身份包 ID、身份包版本和身份包摘要
- 每张规范参考图的角色、用途、内容摘要及变换元数据
- 工作流摘要及最终 `MODEL` 消费路径证明
- 八镜头夹具摘要、提示词模板版本、生成参数和随机种子
- 评分器 ID、版本、实现摘要和阈值版本
- 每镜头输出摘要、分项分数、重试记录、最终状态
- 总分、证据摘要和创建时间

证据以内容摘要为身份，不依赖文件路径或显示名称。导入证据时必须重新计算并核对摘要，不能只信任 JSON 中的声明。

### 3.1 零样本证据

零样本证据必须满足：

- 工作流精确绑定已批准的 Klein 基础模型。
- 所有规范参考图均来自同一版本身份包。
- 最终生成使用的全部 `MODEL` 路径上不存在活动角色 LoRA。
- LoRA 文件、强度、候选配置等字段必须为空。
- 引用图裁切、镜像等变换被记录并纳入工作流或引用清单摘要。

如果工作流中存在活动角色 LoRA，即使输出质量合格，也必须拒绝签发零样本证据。

### 3.2 LoRA 增强证据

LoRA 轨道保留现有严格约束：候选 LoRA 配置必须获批，且同一个获批 LoRA 必须支配全部最终生成 `MODEL` 消费路径。KSampler、CFGGuider 等实际消费者都要纳入证明；旁路采样器、图像混合或展示节点不能伪造 LoRA 绑定。

## 4. 身份参考路由

身份包继续使用 `face_master`、左右侧脸、`hair_back`、`body_front`、`body_side`、`body_back` 等规范槽位。基准运行前生成一份内容寻址的引用清单，并针对镜头明确记录路由：

- 正脸近景：优先 `face_master`，使用受控头肩裁切。
- 左右侧脸：使用对应侧脸；若身份包只提供相反方向，可使用明确记录的水平镜像，不能静默替代。
- 背面：优先 `hair_back + body_back`。
- 全身动作：优先身体参考，并在提示词中明确肢体动作、方向与动态意图。
- 强表情：使用脸部裁切和明确表情指令，身份描述本身保持不变。

裁切、镜像、缩放和参考次序都属于证据的一部分。改变任一项都视为工作流变化，需要重跑基准。

## 5. 八镜头基准与可信评分

基准命令新增显式模式：

```text
--mode zero-shot
--mode lora
```

`zero-shot` 要求已发布身份包，不要求 LoRA；`lora` 额外要求获批 LoRA 配置和终端模型路径证明。两种模式都必须串行执行固定八镜头，不允许用旧输出、参考图拼贴、裁切补救图或回退图替代生成成功。

固定镜头覆盖：正脸近景、45° 半身、左右侧脸、背面、全身动作、强表情、多人/复杂场景以及不同光照。失败时只允许有界重试；每次重试必须记录种子、参考变换和提示词差异。

可信本地评分器提供版本化的 `evaluateCharacterShot` 接口，输出：

- 脸部身份
- 发型结构
- 服装一致性
- 身体比例
- 画面质量与异常检测

权重随镜头类型变化：近景提高脸部分数，背面提高发型分数，远景降低五官权重并提高轮廓、服装和身体比例权重。评分器实现及阈值都必须进入摘要；评分器改变会使旧证据失效。人工复核可以处理边界失败，但不能手工修改分数或直接设置“已就绪”。人工批准如被允许，必须作为带审核人、时间和原因的附加签名，并仍要求机器硬性异常检查通过。

## 6. 发布门禁

零样本轨道只有在以下条件全部成立时才显示“零样本已验证”：

- 八镜头全部生成并被接受。
- 提供器、精确模型、身份包、引用摘要和工作流摘要全部匹配当前生产配置。
- 工作流中没有活动角色 LoRA。
- 使用当前可信评分器和当前阈值版本。
- 脸、发型、服装、身体和质量分项均达到镜头对应阈值。
- 没有人物缺失、串脸、额外人物、严重五官/肢体破损或身份交换。
- 没有回退图、拼贴图或无法追溯的输出。

LoRA 轨道继续执行上述通用门禁，并额外要求候选 LoRA、文件摘要、强度和全部最终模型路径绑定通过验证。

若 Klein 的有效零样本证据与当前配置完全匹配，本机生产选择器可以将其标记为 `ready` 并默认使用。存在同身份版本或更新身份版本的有效 LoRA 证据时，生产选择器优先使用 LoRA 增强轨道；用户仍可显式选择已验证的零样本轨道进行对照或快速生成。

## 7. 失效与迁移规则

- 修改基础模型、提供器、工作流、引用图内容/变换、身份包版本、提示词模板、夹具或评分器：两条轨道的相关证据均失效。
- 修改或替换 LoRA 文件、强度、应用位置或候选配置：仅 LoRA 证据失效，匹配的零样本证据保持有效。
- 新身份包版本不继承旧版本的发布状态。
- 现有合法 LoRA 证据保持原语义；迁移过程不得将其自动转换为零样本证据。
- 现有无签名报告和本次人工观察到的八张输出只能作为诊断资料，不能自动晋升为发布证据。

失效不是删除证据。UI 保留历史记录，并显示当前配置与证据不匹配的具体原因。

## 8. UI 状态

人物资产面板显示彼此独立的状态徽章：

- `零样本已验证`
- `LoRA 已验证`
- `待复核`
- `证据已失效`

面板显示当前模式、模型、身份包版本、最近八镜头结果、评分器版本、证据时间和失效原因。移除现有“没有 LoRA 就永远无法生产”的单一门禁，但不增加手动“设为已就绪”开关。

镜头检查卡继续展示每个分项分数、实际使用的参考图及变换、模型、LoRA（如有）、重试和失败原因。用户选择未验证模式时必须明确标注为实验运行，不能写入发布状态。

## 9. 测试与实施边界

实现采用 TDD，先增加失败测试，再写最小实现。至少覆盖：

- 合法 Klein 零样本证据通过并解锁生产。
- 模式错误、基础模型不符、工作流摘要不符被拒绝。
- 零样本工作流含活动 LoRA 时被拒绝。
- 身份包版本、规范参考摘要或引用变换不符时被拒绝。
- 评分器 ID、版本、实现摘要或阈值不符时被拒绝。
- 任一镜头缺失、失败、回退或低于分项阈值时被拒绝。
- 修改 LoRA 只使 LoRA 证据失效，不误伤零样本证据。
- 现有 LoRA 终端路径证明测试保持通过。
- UI 不提供绕过证据的手动就绪入口，并准确解释失效原因。

单元和集成测试通过后，在 ComfyUI Desktop 上用当前 Klein 工作流重新执行严格八镜头基准。只有自动评分证据完整且门禁通过，才能宣布零样本生产基线完成；仅凭视觉观感不得宣称发布完成。

## 10. 验收结果

完成后，同一人物可以在不训练 LoRA 的情况下，以版本化身份包和 Klein 多参考工作流获得可审计的发布资格；长期主角仍可通过 LoRA 获得更高稳定性。系统始终能回答“这张图用了哪种模式、哪套身份、哪些参考、哪个模型、哪个评分器，以及为什么当前仍然有效”。
